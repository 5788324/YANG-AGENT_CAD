# YGDL/YGDLW — 智能双线管道与对称改宽 V1 (2026-11-06)

状态：SOURCE CANDIDATE / WINDOWS_NOT_TESTED；不可称为已验收 DLL。基于已验收 AutoCAD 2024 RC1 的 main 独立开发，不修改源泉 XD、贱人工具箱或其他 Draft PR。

## 核心定义
双线宽度 = 两条边线间的实际宽度（不是单侧偏移量）。固定中线的对称更新：
- 梁、墙、管：600 mm → 1000 mm，左右各外移 200 mm；1000 → 600，左右各内移 200 mm。
- 反复修改不得累计漂移；弯角须从永久保存的中心路径重新计算两侧，而不是对已偏移线继续做单侧 OFFSET。
- 管道中心线的顶点、bulge、标高和 Handle 在宽度变更前后不变。

## 命令
YGDL：Double（普通双线）或 Pipe（双侧+可见中心线）；输入实际宽度 mm（首次默认 1000），Center/Left/Right 对齐，Miter（斜接）、Bevel（倒角）、Round（圆弧弯头），中心线两端延长；2～96 个同 Z 顶点，回车完成一组继续下一组。命令间开始位置可用 Width 更改下一组宽度，在指定下一顶点时 Undo 撤销上一点。
YGDLW：点选 YangCAD 创建的任意一条左侧、右侧、可见中心线，自动识别所属组、旧宽度和记录的中心路径，输入新宽度，左右两侧重新生成。源左右边线 Handle 会变，中心线 Handle 不变；事务失败自动回滚。
旧插件双线：没有组 XData 时，两次选择普通平行 LINE（端点、标高和长度须对应），测出旧宽并对称修改原 LINE 端点，原 Handle 不变。复杂曲线 / 旧插件多段线无法确认配对时拒绝，防止破坏原图。

## 数据/单位
用户配置写入已有 %LOCALAPPDATA%/YangCADAgent/settings.json：DoubleLineWidthMm、DoubleLineMode、DoubleLineAlignment、DoubleLineCorner、DoubleLineCenterExtensionMm；只有成功绘图/修改才保存。以后执行默认使用上一次数值，不再回到 15。
INSUNITS=0 默认视作毫米，主动提醒用户；1 英寸、2 英尺、4 毫米、5 厘米、6 米、7 千米自动换算到图元单位；其他未知单位拒绝。
所有新建双线使用原生 AutoCAD Polyline，中心线可显示。将中心路径坐标 + bulge、Z、宽度、成组 GUID、各成员角色保存为本插件专用 XData（YANGCAD_DUAL_V1），保存重开后仍可编辑。严格检查成员数量、锁层、重复 GUID、原线是否被手动改形、管道中线是否被手动改形。
沿中心路径通过 AutoCAD 原生 GetOffsetCurves 正负半宽生成两侧。偏移生成超过一条曲线、过近转角、内弧半径不足或路径自交时直接取消，不制造不可靠墙线。
本版中心线绘制在当前图层上，颜色/线型/中心线比例由 AutoCAD 后期属性调整；三通、批量旧多段线配对、复杂交叉口自动清理暂不支持。

验收：见 tasks/DUAL_LINE_WINDOWS_SMOKE_20261106.md，尤其中心不变、600→1000、圆角、原生 _.U、Loaded DLL 和持久化组信息。

## 2026-11-06 UCS / layer / display robustness review
YGDL uses the native AutoCAD .NET GetOffsetCurves, AppendEntity and Transaction APIs, not the AutoLISP entmake mechanism or scripted PLINE command. GetPoint returns WCS coordinates. V1 only supports WCS-horizontal XY drawing planes; a rotated-around-Z UCS works, but a tilted UCS now returns a clear rejection rather than silently flattening picked points into the wrong plane. The command also rejects a locked, frozen or off current layer before appending.
After each group is committed, Editor.Regen() is requested to refresh the viewport. This is NOT a live preview while moving the cursor or picking intermediate vertices; DrawJig or transient graphics is a separate follow-up task.
An uploaded comparison LISP also registers c:YGDL. Do not load it simultaneously with YangCAD .NET YGDL: rename one command or use isolated AutoCAD processes to prove which implementation is running. Switching from entmake to command PLINE does not by itself guarantee success in every UCS/viewport/layer state.
